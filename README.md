# onePress

> A bridge toolkit for OpenSpec × Superpowers × Tailwind/shadcn — lets designer-less, developer-led teams install a complete frontend engineering discipline into any repo with a single prompt.

onePress packages the v3.0 minimal frontend workflow as a distributable, idempotently installable, upgradeable harness template pack: BMAD-style UX auto-derivation (`ui_contract` YAML contract), sandbox-as-production (UI scaffold output + floating State Bar acceptance), second-level static gates (tsc + Token regex + pure-logic Hook TDD), and a component registry (`docs/ui-components.md`).

**First-class support for two AI coding harnesses**: `.qoder/` and `.opencode/`. Zero runtime dependencies — any LLM with file read/write capability can perform the install.

---

## Prerequisites

- (Recommended) OpenSpec CLI installed: `npm install -g @fission-ai/openspec@latest` (Node 22.12+) for the downstream `/opsx:*` workflow
- An AI coding assistant (Qoder / OpenCode / any agent) with file and command access

## Quick Start (30-second install)

Paste the following prompt **in full** to the AI assistant inside the target repo:

```text
Install the onePress frontend workflow toolkit (OpenSpec × Superpowers × Tailwind/shadcn bridge) into this repository:

1. Fetch the template pack into a local temp directory via sparse checkout:
   git clone --depth 1 --filter=blob:none --sparse https://github.com/rooho/onePress.git <temp-dir>
   then run inside <temp-dir>: git sparse-checkout set onePress

2. Read <temp-dir>/onePress/INSTALL_PROMPT.md in full and strictly follow its five sections:
   ① Preflight → ② Layered install → ③ Idempotency & upgrade → ④ Acceptance checklist → ⑤ Finalize
   (Template files MUST be written verbatim to target paths. Red lines: never overwrite
   project-level assets or business code.)

3. When done, report the acceptance checklist results and the onePress.lock contents.
```

After installation, the repo gains:

| Location | Contents |
|----------|----------|
| `.opencode/` | `opencode.json` + `agent/ux-architect.md` + `commands/opsx-{new,apply,verify}.md` + `skills/superpowers-tdd/` |
| `.qoder/skills/onepress-discipline/` | Four iron rules + TDD discipline (Qoder carrier) |
| `openspec/schemas/superspec/` | superspec schema (schema.yaml + 9 templates = 10 files) |
| `onePress.lock` | Version and protected-assets manifest |
| `docs/ui-components.md` | Component registry (initialized on first install; skipped if it already exists) |

> Manual alternative: download this repo's `onePress/` directory locally, then hand the full text of its `INSTALL_PROMPT.md` to your AI assistant — same result.

## Daily Usage After Install

```text
/opsx:new my-feature      # Contract init: proposal/design + ui_contract YAML at the bottom of design.md (BMAD UX auto-derivation)
/opsx:apply               # Sandbox-as-production: Stage 1 UI scaffold (floating State Bar, 10s acceptance) → Stage 2 schema wiring
/opsx:verify              # Second-level static gates: tsc + Token regex + Hook TDD + four-state spot check
/opsx:archive             # Archive and incrementally append components to docs/ui-components.md
```

Core contract example (bottom of `design.md`, auto-generated by AI):

## Asset Layering & Upgrade Policy

| Layer | Assets | Upgrade behavior |
|-------|--------|------------------|
| Harness-level (onePress maintained) | `commands/`, `skills/`, gate scripts, `openspec/schemas/superspec/` | Full overwrite (delete-then-write, no stale residue) |
| Project-level (target-repo owned) | `docs/ui-components.md`, `openspec/changes/` | Skip if exists (Protect Local), never overwritten |
| Local modifications | Uncommitted changes to harness files in the target repo | Detected → prompt and skip that item |

Upgrade = re-run the Quick Start prompt with the new version. `onePress.lock` records the version and protected assets; if missing or corrupt, the installer treats it as a fresh install (project-level assets remain protected).

## Uninstall / Rollback

Remove everything installed except the assets listed in `onePress.lock`'s `protectedAssets`:

```text
Delete .opencode/ (if created by onePress), .qoder/skills/onepress-discipline/,
openspec/schemas/superspec/, and onePress.lock;
keep docs/ui-components.md and openspec/changes/ (project-level assets).
```

## FAQ

**Q: The target repo has no OpenSpec. Does onePress still work?**
A: It can install, but the `/opsx:*` workflow and `ui_contract` parsing require OpenSpec. Run `openspec init` first.

**Q: Will my existing `.qoder/` be damaged?**
A: No. onePress only adds `skills/onepress-discipline/` and inserts a one-line skill reference at the top of existing commands; command bodies are untouched.

**Q: What happens on repeated installs?**
A: Idempotent. Harness assets are overwritten to match the template exactly; project-level assets are skipped if present; `onePress.lock` version is refreshed.
